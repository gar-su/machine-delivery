# 机器投放系统 · 功能需求文档（PRD）

> 版本 v1.0 · 面向开发 · 取代原六份 spec 的执行侧设计

## 1. 概述

### 1.1 系统定位

机器投放系统是**触发编排层**：接收触发信号，**新建自动化任务**。系统自身不创建广告、不维护账户池、不跨账户复制——这些能力全部由既有**自动化任务**承担。

> 术语说明：本文档「自动化任务」指既有自动建任务的执行层能力，**涵盖 TikTok 与 Meta 两条渠道**。文中不再单独指向某一渠道。

> 术语说明：「模板」指机器投放后台运营维护的投放方案（场景 × 语言 → 一套投放方案）；「自动化任务配置」指自动化任务侧承载预算/账户/竞价等参数的配置，「模板」通过引用指向「自动化任务配置」。二者不混用「模板」一词。

### 1.2 核心价值

把两件本由运营/优化师手动做的事，变成自动触发：

1. **新剧测新**：剧上线 → 自动生成无清单 → 拉起测试投放。
2. **跟投**：smart_ad_put 看数据决策 → 自动拉起跟投投放。

### 1.3 两条路径对比

| 维度 | 新剧测新 | 跟投 |
|---|---|---|
| 触发源 | 剧上线事件 | smart_ad_put 决策 |
| 是否人工确认 | 是（清单 + 确认）| 否（全自动）|
| 目标粒度 | 短剧 | 短剧 / 广告计划 / 素材 |
| 素材 | 任务筛选扫描（最近上传）| 随决策目标 |

### 1.4 原型界面

- 原型：https://gar-su.github.io/machine-delivery/

## 2. 核心概念：触发信号

机器投放系统的唯一输入是触发信号，共两类。

### 2.1 信号公共字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `signal_id` | string | ✅ | 信号唯一标识，幂等键，重复投递不重复建任务 |
| `signal_type` | enum | ✅ | `NEW_DRAMA_ONLINE` / `FOLLOW_UP` |

### 2.2 `NEW_DRAMA_ONLINE`（新剧上线）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `shortplay_id` | string | ✅ | 上线短剧 ID |
| `shortplay_name` | string | ✅ | 短剧名 |
| `script_no` | string | ✅ | 剧本编号（如 `LA001`），与 `shortplay_name` 拼接展示 |
| `language_code` | string | ✅ | 短剧语言，用于模板分流 |
| `online_at` | datetime | ✅ | 上线时间 |

> 展示规则：短剧在后台展示时，名称格式为「剧本编号 + 短剧名」，如 `LA001 霸总的替嫁新娘`。业务上短剧分两级——剧本（编号 `LAxxx`）与短剧，后台展示短剧需带上所属剧本编号。

### 2.3 `FOLLOW_UP`（跟投决策）——即来自智能基建 smart_ad_put 项目

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `target_dimension` | enum | ✅ | `product` / `campaign` / `material` |
| `target_id` | string | ✅ | 对应 shortplay_id / campaign_id / material_id |
| `script_no` | string | 否 | 目标为短剧时携带剧本编号（如 `LA001`），展示时与短剧名拼接 |
| `reason` | string | 否 | 决策理由（可读，用于看板展示）|

> 跟投的决策统一由 smart_ad_put 产出（含素材级，素材级决策能力由其补齐）。

> **本期范围**：smart_ad_put 系统本身尚未完成，**两个系统的对接本期不做**，待智能基建系统做完后再对接。本节信号定义保留，作为对接时的设计依据。

## 3. 功能一：新剧测新

### 3.1 功能说明

新剧上线后，系统自动生成测新清单，经人工确认后拉起测试投放任务。素材不在此环节选定，由自动化任务按其素材筛选配置（选用「最近上传的素材」即可）多轮扫描获取新素材。

### 3.2 触发规则

- 触发条件：短剧进入「已上线」状态。
- 触发模式：**默认自动 + 可手动**。默认剧上线即自动生成清单；特定剧可配置关闭自动，改人工发起。

### 3.3 处理流程

```
剧上线 → 生成测新清单 → 人工确认 → 按模板拉起新任务
```

### 3.4 人工确认规则

人工确认是测新流程唯一介入点，需处理两件事：

1. **选模板**：默认预选当前操作人自己的默认模板（按场景 × 语言维护，每人不同），人工可换选。
2. **设排期**：可设投放排期时间，未设默认立即投放。

确认动作的结果：**通过 / 换模板 / 驳回 / 排期通过**。人工不逐个确认预算、竞价等详细参数（由模板承载）。

测新清单支持按状态、短剧、时间筛选；其中短剧筛选支持输入**短剧名或剧本编号**（如 `LA001`）检索。

支持**批量操作**：可勾选多条「待确认」清单，批量通过 / 批量驳回；**批量通过时可同时设定统一排期**（东八区，留空=立即投放）。不可操作状态（已通过 / 已驳回）的清单不可勾选。

支持**排期**：清单可设投放排期时间，确认后**立即启动自动化任务**，排期作为参数传入自动化任务的排期字段，由任务到点执行。排期时区为**东八区**，列表展示与设置界面均须标注。未设排期立即执行。

### 3.5 异常与边界

| 场景 | 处理 |
|---|---|
| 无匹配模板（该语言未配模板）| 跳过并告警 |
| 人工驳回 | 不投，清单标记驳回，不拉起任务 |
| 同一 signal_id 重复 | 幂等去重，不重复生成清单 |

### 3.6 验收

- [ ] 剧上线后，自动生成测新清单
- [ ] 人工确认通过后，成功拉起对应测试任务
- [ ] 同 signal_id 重复投递不重复生成清单

## 4. 功能二：跟投

### 4.1 功能说明

> **本期不做**：跟投依赖 smart_ad_put 产出 `FOLLOW_UP` 信号，而 smart_ad_put 系统尚未完成，**本期先不做两系统对接**，待智能基建系统做完后再做。本节内容保留为对接时的设计依据。

smart_ad_put 根据投放数据判定某目标值得继续投放时，系统自动拉起跟投任务，无需人工介入。

### 4.2 触发规则

- 触发源：smart_ad_put 决策。
- 模式：**全自动，无人工确认**。

### 4.3 处理流程

```
smart_ad_put 决策 → 按语言分流选默认模板 → 新建跟投任务
```

### 4.4 异常与边界

| 场景 | 处理 |
|---|---|
| 决策数据异常（必填字段缺失）| 跳过并告警 |
| 无匹配模板 | 跳过并告警 |
| 同 signal_id 重复投递 | 幂等去重，不重复建任务 |

### 4.5 验收

- [ ] 决策产生后自动新建跟投任务
- [ ] 决策 → 新任务创建完成可查
- [ ] 同 signal_id 重复投递不重复建任务

## 5. 公共规则

### 5.1 模板分流

- 分流维度 = 场景（测新 / 跟投）× 语言（`language_code`）。
- **跟投**：全自动，按「场景 × 语言」的系统默认模板执行，无个人之分、无人工换选。
- **测新**：确认界面默认预选**当前操作人自己的默认模板**。每位操作人在后台按「场景 × 语言」独立维护自己的默认模板（每人不同），打开确认界面时预选，可再人工换选模板库中任意其他模板。
- **测新与跟投是两套不同的模板**——同一语言下，测新场景与跟投场景绑定各自的模板。
- 模板库预置多个模板，各代表不同投放规模/参数；测新模板侧重试探（小预算），跟投模板侧重放量（按策略规模）。

### 5.2 模板分层

| 层 | 对象 | 职责 |
|---|---|---|
| 第2层 | 模板（机器投放后台） | 运营维护的投放方案，按「场景 × 语言」分流，通过引用指向第1层自动化任务配置 |
| 第1层 | 自动化任务配置 | 全部执行参数（账户包/账户数/预算/竞价/优化目标/版位/定向/投放天数/止投）|

> 预算、账户包、账户数、竞价、优化目标、版位、定向、投放天数、止投条件等执行参数，全部由第1层自动化任务配置承载。机器投放系统不重复定义、不传递，仅通过模板引用指向自动化任务配置。

### 5.3 与自动化任务的边界

- 机器投放系统对自动化任务的**唯一动作是新建任务**。
- 传入自动化任务的字段由**信号 + 确认/分流结果**共同决定：

| 字段 | 测新 | 跟投 | 说明 |
|---|---|---|---|
| `shortplay_id` | ✅ | 目标为短剧时 | 短剧 ID |
| `target_dimension` | — | ✅ | product / campaign / material |
| `target_id` | — | ✅ | campaign_id / material_id（短剧目标时即 `shortplay_id`）|
| `script_no` | ✅ | 短剧目标时 | 剧本编号（如 `LA001`），展示时与短剧名拼接 |
| `shortplay_name` | ✅ | — | 短剧名 |
| `schedule_at` | ✅ | — | 排期时间（东八区），作为参数传入自动化任务的排期字段，任务到点执行；未设则立即执行 |
| 模板引用 | ✅ | ✅ | 选定的模板 → 自动化任务配置 |

- **排期**：测新确认后**立即启动自动化任务**，排期作为参数传入自动化任务的排期字段，由任务按排期执行。
- **素材**：测新不传素材清单，素材由自动化任务按其素材筛选配置（选用「最近上传的素材」即可）多轮扫描获取新素材。
- 执行参数（预算/账户包/账户数/竞价/优化目标/版位/定向/投放天数/止投）**不在此传递**，全部由模板引用的自动化任务配置承载。

### 5.4 信号通道

- 机器投放系统提供一个信号入口，接收 smart_ad_put 决策与剧上线事件。
- 具体实现（文件/API/MQ）不锁，开发阶段定。

### 5.5 幂等

- 以 `signal_id` 为幂等键，同信号重复投递不重复建任务。

### 5.6 权限

- **测新清单不分发**：所有用户可见相同的待确认清单（当前无按人分配规则；后续如需按人分配，先定义分配规则再补）。
- **操作记录按人可见**：普通用户仅可查看自己的操作记录；管理员可查看所有记录。
- **投放结果按操作人分隔**：投放结果页（自动化任务/广告系列/广告组/广告透传）普通用户仅可见与自己相关（测新确认人 = 自己）任务的结果，管理员可查看全部；自动化任务需维护归属人。

## 6. 执行记录与看板

系统保留**管理看板**，展示两类信息：

1. **编排记录**：机器投放自身收到什么信号、起了哪些任务、成功/失败。
2. **投放结果聚合**：透传自动化任务的投放结果（广告系列/广告组/广告/账户状态）。

管理后台共四个顶层页面：**运行看板**（内三页：运行概览 / 执行记录 / 投放结果，纯读）、**测新清单**（见 §3，含确认操作）、**模板管理**（模板库维护，见 §5）、**告警**（见 6.4）。

### 6.1 运行概览

展示机器投放自身近期的编排情况，不含业务指标（消耗/ROI 属投放结果视角）。

| 指标 | 数据来源 | 说明 |
|---|---|---|
| 收到信号数 | 编排记录（signal_id 去重）| 累计/今日接收的触发信号数 |
| 起任务成功 / 失败 / 跳过 | 编排记录 | 按起任务结果计数 |
| 待确认清单数 | 测新清单 | 待人工确认的测新清单数 |
| 无匹配模板跳过 | 编排记录 | 异常告警统计 |

### 6.2 执行记录

展示机器投放的全部编排动作留痕，涵盖测新与跟投两类信号。

| 字段 | 说明 |
|---|---|
| signal_id | 信号唯一标识 |
| signal_type | 测新 / 跟投 |
| target_dimension + target_id | 目标（短剧/广告计划/素材）|
| 选用模板 | 默认 or 人工换选的模板 |
| 自动化任务ID | 本次新建的自动化任务标识（1 个信号对应 1 个任务）|
| 状态 | 当前状态（见 6.6 状态列表）|
| 操作人 | 自动触发为「系统」，测新为确认人 |
| 时间 | 信号接收与起任务时间 |

支持筛选：信号类型 / 状态 / 操作人 / 时间范围 / target_id。

> 测新的「待确认」阶段由「测新清单」管理；人工确认通过、拉起任务后，其动作计入本页执行记录。

### 6.6 编排状态模型

一次编排动作从信号接收到拉起任务、再到任务内部跑完，经过**三个环节**。每个环节有独立的状态，横向依次展示，构成一条编排的状态链：

```
建任务 → 运行 → 广告创建
```

执行记录与运行概览的「状态」列，横向展示这三个环节各自的状态值；某一环节未到时以「—（待定）」表示，前置环节失败/跳过时后续环节不再展示。

**环节一：建任务（机器投放自身 → 自动化任务）**

| 状态值 | 含义 |
|---|---|
| `建任务中` | 信号已接收，正在调用创建接口 |
| `成功` | 自动化任务已成功创建 |
| `失败` | 调用创建接口失败 |
| `跳过·无匹配模板` | 语言未配置模板 |
| `跳过·数据异常` | 信号必填字段缺失 |
| `已驳回` | 测新人工驳回 |

**环节二：运行（直接取自动化任务的运行状态）**

| 状态值 | 含义 |
|---|---|
| `启动` | 自动化任务处于启用状态 |
| `暂停` | 自动化任务处于暂停状态 |

**环节三：广告创建（任务一轮执行结果）**

| 状态值 | 含义 |
|---|---|
| `成功` | 本轮广告全部建成功 |
| `部分成功` | 部分账户/素材建成功（如 N 个账户中 M 个成功）|
| `失败` | 本轮广告未建出 |

> 关键：状态链是**三环节各自独立取值**，不是单一状态。例：某编排「建任务=成功、运行=完毕、广告创建=部分成功」，表示任务建好也跑完了，但复制到多个账户时只有部分账户建出了广告。

### 6.3 投放结果

透传自动化任务的投放结果，供人工巡检。

| 页面 | 透传内容 |
|---|---|
| 任务列表 | 已建的自动化任务及其状态 |
| 广告系列 | 广告系列状态/预算/竞价策略/账户 |
| 广告组 / 广告 | 逐级透传，含商品库关联、行动号召 |

该页等同自动化系统现有「自动化任务 / 广告系列 / 广告组 / 广告」列表的只读视图。

该页**按操作人分隔**（见 5.6）：普通用户仅可见与自己相关（测新确认人 = 自己）任务的结果，管理员可见全部。

### 6.4 告警

| 场景 | 提示 |
|---|---|
| 无匹配模板 | 告警，提示某语言未配模板 |
| 决策数据异常 | 告警，提示信号字段缺失 |
| 起任务连续失败 N 次 | 日志 + 告警（N 默认 3）|
