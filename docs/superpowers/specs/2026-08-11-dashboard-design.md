# 管理看板设计（序5 · 纯读展示端）

> 日期：2026-08-11 · 状态：草稿待审 · 关联：《项目整体规划》（M1 线⑤管理看板）
> 本文档是六个模块设计的第五个（序5），定义看板的页面需求、数据来源与刷新频率。

## 1. 定位与范围

管理看板是机器投放系统执行侧的**纯读展示端**：查询执行记录、账户池状态等执行侧自有数据，供人工巡检。**无任何写入口**——不改配置、不改账户状态。

**本期做**：四页面（运行概览 / 规则列表 / 执行记录 / 账户池状态）、纯读 REST API + 前端 SPA。
**本期不做**：写操作（改配置/改账户状态）、业务指标展示（消耗/ROI 属决策端视角，本看板不含）、登录鉴权（内网可访问）。

## 2. 页面需求

### 2.1 运行概览 — 执行侧指标

只含执行端自有数据，不含业务指标（消耗/ROI）。

| 指标 | 数据来源 | 说明 |
|---|---|---|
| 决策接收数 | 执行记录（decision_id 去重） | 累计接收决策数 |
| 执行成功 / 失败 / skipped 数 | 执行记录（status） | 按状态计数 |
| 成功率 | 执行记录 | 成功 / 应执行 |
| 失败原因 Top | 执行记录（error_reason） | 聚合归因 |
| 规则命中 Top | 执行记录（rule_id） | 命中统计（口径同 §2.2） |
| 账户池可用账户数 | 账户池（序3） | 各池 active 账户数 |

### 2.2 规则列表 — 从决策归并

- 展示 **rule_id + 累计命中数**：从执行记录按 `rule_id` 聚合，去重自动生成清单。
- 无规则元数据同步：规则定义（规则名/条件）由 smart_ad_put 决策端持有，本看板只展示 ID 与命中数，不额外同步元数据。
- 支持时间范围筛选。

### 2.3 执行记录

- 字段：`decision_id` / `rule_id` / `action` / `target`（shortplay_id / 语言 / 素材）/ `status` / `error_reason` / `platform_task_ids` / `copied_accounts` / `created_at`。
- 筛选：状态 / 时间范围 / rule_id。
- 幂等可查：同 `decision_id` 重复投递只保留一条记录（唯一索引）。

### 2.4 账户池状态

- 池子列表 + 各池账户（platform / status / labels / 凭证引用）。
- 可用账户数（active）展示。
- 只读对接序3 账户池：状态变更由人工维护（序3），看板不改。

## 3. 数据来源

| 页面 | 数据来源 |
|---|---|
| 运行概览 | 执行记录（序1）+ 账户池（序3） |
| 规则列表 | 执行记录（序1，rule_id 聚合） |
| 执行记录 | 执行记录（序1） |
| 账户池状态 | 账户池（序3） |

看板只读消费各模块数据，不跨模块写。

## 4. 刷新频率

- 对齐 30min 调度：每轮调度完成后刷新（数据就绪后展示）。
- 前端支持手动刷新。

## 5. 验收口径

- 四页面均可访问，纯读无写入口。
- 规则命中数 = 执行记录中该 `rule_id` 的累计命中数（可核对）。
- 账户池状态与序3 数据一致（active 可用数正确）。
- 看板只出现已产生执行记录的规则（从决策归并，不显示无命中规则清单）。

## 6. 依赖与待对齐

- **依赖**：序1 决策契约（`rule_id` 字段）、序1 执行记录、序3 账户池。
- **待对齐**：看板读取执行记录/账户池的接口形态（看板 REST 直查 vs 经模块接口）；时间范围筛选粒度。
- **假设**：内网可访问、无鉴权；展示频率 30min 与调度对齐；规则定义元数据由决策端持有，本看板不同步。
