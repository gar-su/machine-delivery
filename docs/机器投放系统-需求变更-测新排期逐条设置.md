# 机器投放系统 · 需求变更单：测新排期逐部设置
> 变更单 CR-003（2026-10-20）· 目标版本 v1.8 · 影响界面：测新确认弹窗 · 对应 PRD §2.2 / §3 / §5.3 / §7
## 1. 背景与目标
测新确认弹窗原设「本批统一排期」——一个时间对本批所有短剧生效。实际投放中同一批短剧的上线时间各不相同，预上线短剧尤其明显：统一排期要么迁就最早的剧，要么让先上线的剧空等，运营只能把一批拆成多批分别发起。与此同时，上游 `first_delivered_at`（初次投放时间）已在清单中展示（CR-001 / CR-002），却只能看、不能直接用作排期。
本次把测新排期从「本批统一」改为「逐部设置」，并在上游初次投放时间尚未到时默认带出该值；同时明确该时间的时区口径。
| 现状 | 本次变更 |
|---|---|
| 一个排期对本批所有短剧生效 | 每部短剧各设一个排期 |
| 排期无默认值 | 仅当初次投放时间晚于当前东八区时间时默认带出，否则留空 |
| 初次投放时间只用于展示与筛选 | 同时作为排期默认值 |
| 时区口径散见于各文档，未说明是否换算 | 明确上游即东八区，本系统原值直取、不做换算 |
## 2. 变更内容
### 2.1 排期改为逐部设置
测新确认弹窗内的排期由「一个时间 + 对本批所有短剧生效」改为列出已选短剧清单（剧本编号 + 短剧名），每部短剧各一个排期输入（东八区）。弹窗仍以一次批量确认作为唯一确认动作，逐部取值后一并提交。
| 维度 | 变更前 | 变更后 |
|---|---|---|
| 排期输入 | 1 个 | N 个（N = 本批短剧数）|
| 作用范围 | 本批全部 | 各自所属的那部短剧 |
| 已选短剧清单 | 纯文本罗列 | 一行一部，与排期输入同一张表 |
| 留空口径 | 本批统一立即投放 | 该部立即投放，不影响同批其他短剧 |
### 2.2 排期默认值规则
排期输入只在一种情况下预填：该短剧上游 `first_delivered_at`（初次投放时间）**晚于当前东八区时间**。预填值为上游原值，不做派生。
以下两种情况排期一律置为空（等同立即执行）：
| 情况 | 处理 |
|---|---|
| 初次投放时间早于或等于当前东八区时间 | 置为空，不预填已过去的时间 |
| 初次投放时间为空（未投放过，清单显示 `—`）| 置为空 |
初次投放时间在判断时已过去是常态——它记录的是「第一次被投放」的时刻，多数短剧早已投过。因此该默认值实际只对「上游排在未来首次投放」的短剧生效。
用户可逐部改写。关闭弹窗后本次改动不保留，下次打开重新按上述规则计算。
### 2.3 时区口径
排期时区固定东八区，逐部输入的取值即按东八区理解。
**上游 `first_delivered_at` 由上游按东八区填写**，本系统原值直存、传参前不做任何时区换算——上游时间与本系统排期口径一致，无需转换。
### 2.4 不受影响的范围
跟投确认弹窗的排期保持「本批统一排期」不变，其需求以 `docs/PRD-机器投放系统-支持跟投信号接入和绑定任务模板多选.md` §3.4 为准。本次仅改测新。
## 3. 不在本次范围
- 跟投排期（保持本批统一排期）
- 批量填充 / 一键套用同一排期
- 排期的到点执行实现（仍由自动化任务承载）
- 后端 API 实现（本次仅后台原型与文档）
## 4. 验收
- [ ] 测新确认弹窗内每部已选短剧各有一个排期输入，不再有「对本批所有短剧生效」的统一排期
- [ ] 排期仅在上游初次投放时间晚于当前东八区时间时预填该值
- [ ] 上游初次投放时间早于或等于当前东八区时间时，该剧排期默认为空，确认后按立即投放写入执行记录
- [ ] 上游初次投放时间为空的短剧排期默认为空，确认后按立即投放写入执行记录，且不影响同批其他短剧
- [ ] 逐部改写排期后，执行记录中各短剧的时间分别为各自设定的值
- [ ] 上游初次投放时间为东八区原值直取，本系统不做时区换算
- [ ] 跟投确认弹窗排期仍为本批统一排期
