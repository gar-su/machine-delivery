# 机器投放系统 · 需求变更单：执行记录展示广告产出
> 变更单 CR-005（2026-10-27）· 目标版本 v1.0（独立需求文档）· 影响界面：运行看板 / 执行记录 · 对应需求文档 `docs/机器投放系统-需求文档-执行记录展示广告产出.md`
## 1. 背景与目标
执行记录只记录绑定动作，不记录下游实际产出，运营无法判断每个信号建了多少广告实体、是否上传成功。本次把下游三层广告产出引入执行记录，保持编排层不接管执行。
| 现状 | 本次变更 |
|---|---|
| 执行记录无产出数据 | 新增「广告计划 / 系列」「广告组」「广告」三列，按 Meta / TikTok 两行展示 |
| 下游实体与信号无关联键 | 下游建实体时回写 `signal_id`，本系统按信号聚合 |
| 历史记录无产出数据 | 显示 `—`，不做回溯 |
## 2. 变更内容
- 执行记录在「自动化任务」后插入三列，单元格格式为「平台 总数 (成功/失败/待上传)」，Meta 在上、TikTok 在下。
- 统计层级：Campaign（Meta 广告计划 / TikTok 广告系列）、Ad Set（广告组）、Ad（广告）。
- 归属：下游 auto_put / auto_put_tiktok 创建实体时写入 `signal_id`；同一信号跨平台、跨任务汇总为一行。
- 状态：沿用下游三态（待上传 / 上传成功 / 上传失败），三层独立计数，重试只更新状态不新增计数。
- 时延：绑定成功后 10 分钟内可见，状态变化 10 分钟内更新；实现方式开发期定。
## 3. 不在本次范围
- 下钻明细页、按产出数量筛选或排序
- 历史信号回溯补齐
- 绑定流程、默认自动化任务、信号契约的改动
- 原型 `index.html` 同步（线上列与原型列不一致，另行处理）
