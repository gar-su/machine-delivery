# 机器投放系统 · 本期需求说明
> 2026-10-16 · 面向评审 · 覆盖本期全部改动 · 权威细则见 PRD v1.5 与《机器投放系统-跟投需求》，本文档不替代二者
## 1. 一句话
本期做两件事：**把跟投从「不做」改成「接入」**，并把**默认自动化任务从「每个键一条配置」改成「可配多条、每条可启停」**。
## 2. 背景
原口径是「跟投依赖上游智能基建 smart_ad_put，本期不做两系统对接」，系统与试点范围都只覆盖新剧测新。本期决定同时推进跟投：跟投的接收端、配置界面、执行记录一并建成。
另一条线来自实操。原「默认自动化任务」模型是「每个键一条配置，各绑一条 Meta 任务与一条 TikTok 任务」，且**已覆盖的语种禁止重复新增**。这条规则在真实投放里站不住：
- 同一语种 / 组合常需要同时投到多个账户包，一条配置不够
- 想临时收口某个任务，只能整条删掉，恢复时要重新配
所以把唯一性约束换成**多条 + 逐条启用状态**：约束取消，控制权交给启停。
## 3. 改动清单
### 3.1 跟投接入
| 项 | 原口径 | 本期 |
|---|---|---|
| 跟投对接 | 本期不做，待 smart_ad_put 完成后再说 | 本期接入，接收端、配置界面、执行记录一并建成 |
| 试点范围 | 仅新剧测新（批量测新）；跟投不接入 | 新剧测新 + 跟投，两条路径均接入 |
| 触发模式 | — | 全自动：信号到达即绑即投，无人工确认、无排期 |
跟投需求独立成文：`docs/机器投放系统-跟投需求.md`（信号契约、处理流程、配置与权限、异常、验收）。
### 3.2 `FOLLOW_UP` 信号契约
| 变更 | 内容 |
|---|---|
| 新增 | `shortplay_id`（必填）：目标所属短剧，用于反查语种；`product` 级与 `target_id` 同值 |
| 删除 | `script_no`：剧本编号由机器投放从短剧库反查取得，上游不再补 |
| 新增 | `signal_type` 取值 `FOLLOW_UP`（上游现为 `Decision.type` 动作枚举）|
| 映射 | 上游 `decision_id` → 本系统 `signal_id`（幂等键）|
**语种不再由信号携带**：机器投放按 `shortplay_id` 反查短剧库取得，短剧库与测新清单为同一数据源。三种目标维度走同一条路径——短剧级用 `target_id`，广告计划 / 素材级用 `shortplay_id`，最终都落到一部短剧。
### 3.3 跟投按「目标维度 × 语种」路由
| 项 | 测新 | 跟投 |
|---|---|---|
| 路由键 | 语种 | 目标维度 × 语种 |
| 维度取值 | 仅短剧 | 短剧 / 广告计划 / 素材 |
同一语种下三个维度**各配一组、互不通用**——短剧级跟投与素材级跟投的账户包、预算、竞价本就不同，不能共用同一批任务。
### 3.4 默认自动化任务：多条 + 启停
| 项 | 原规则 | 本期规则 |
|---|---|---|
| 一条配置 | 键 + 一条 Meta 任务 + 一条 TikTok 任务 | 键 + 一条 Meta 任务 + 一条 TikTok 任务 + 状态 |
| 重复新增 | 已覆盖的键禁止重复新增 | 不限制，同一个键可配任意多条 |
| 解析 | 取该键的唯一条目 | 取该键下全部启用中的条目，把目标绑进它们的全部任务 |
| 停用 | 无此概念 | 完全不参与解析——不绑定，也不计异常 |
| 行操作 | 编辑 / 删除 | 编辑（键固定）/ 启用·停用 / 删除（只删这一条） |
「已覆盖禁止重复新增」整条规则取消，解析只认启用中的条目——停用即退出。配几条，就决定一次会投到几处。
**适用范围**：测新与跟投两个场景一致，只是键不同（测新 = 语种，跟投 = 目标维度 × 语种）。
### 3.5 素材维度的任务约束
跟投在「素材」维度下，绑定任务的下拉**只列指定了素材类型的自动化任务**；短剧、广告计划维度不受限。
依据：素材级跟投的目标是具体素材，承载它的自动化任务必须声明自己处理的素材类型，否则投不到点上。
### 3.6 跟投配置的权限
| 场景 | 归属 | 谁能用 |
|---|---|---|
| 测新 | 按当前操作人逐人一版 | 所有人 |
| 跟投 | 「系统」全局一版 | 仅管理员可见、可增删改与启停 |
跟投没有人工环节，配置不该有个人之分；普通用户看不到跟投 tab。
### 3.7 执行记录
| 项 | 本期 |
|---|---|
| 任务列 | 列出该键下全部启用条目所涉任务，形如 `meta_a、meta_b / tt_a、tt_b` |
| 操作人 | 跟投固定「系统」 |
| 异常 | 该键下没有启用中的条目（未配置，或配置全被停用）→ 跳过·无默认自动化任务 |
| 页面与筛选 | 不新增，沿用现有执行记录（类型筛选已含「跟投」）|

## 5. 开投前置（阻塞项）
跟投全自动、无人工确认闸门，信号到达即绑定即产生消耗。以下三项未闭环则不开投，止损线是它唯一的闸门：
1. **信号通道**：文件 / API / MQ 定一种并约定送达格式（上游现输出本地 JSON 文件）
2. **素材级决策能力**：上游现有素材生命周期检测基于行业经验设计、无真实素材数据，`material_*` 阶段被并入 `campaign`；需接入素材级数据源并产出素材级跟投决策
3. **阶段 → 跟投映射表**：上游 lifecycle 判定中哪些阶段映射为「跟投」，需定表
另需上游落定 §3.2 的契约字段（`shortplay_id` 落地、`script_no` 下线、`signal_type` 对齐）。
## 6. 验收
- [ ] 跟投配置全局一版、仅管理员可见可改，普通用户看不到跟投 tab
- [ ] 默认自动化任务可切换「测新 / 跟投」两个场景；跟投表含目标维度列，两表均含状态列
- [ ] 同一个键可新增多条，不再拦截重复；每条可编辑（键固定）、启用 / 停用、删除（只删这一条）
- [ ] 解析只取启用中的条目；停用的条目既不绑定也不计异常
- [ ] 测新批量绑定与跟投信号绑定都绑进该键下全部启用条目所涉的全部任务
- [ ] 素材维度下任务候选只列指定了素材类型的任务；短剧、广告计划维度不限
- [ ] `FOLLOW_UP` 信号按 `shortplay_id` 反查语种，按「目标维度 × 语种」解析，全自动绑定，无人工介入
- [ ] 反查失败 → 跳过·数据异常；该键无启用条目 → 跳过·无默认自动化任务；同 `signal_id` 重复投递不重复绑定
- [ ] 执行记录任务列可列出多条任务；跟投记录操作人为「系统」，可按类型「跟投」筛出
- [ ] 跟投与测新不互斥，同一目标可同时存在于两类任务
