# PRD · 机器投放系统 —— 支持跟投信号接入和绑定任务模板多选
> 版本 v1.2 · 2026-10-26 · 面向开发与需求评审 · 本文档是**跟投**与**默认自动化任务多条目模型**的唯一需求源；`docs/机器投放系统-功能需求.md`（PRD v1.9）§2.3 与 §4 只作指针。v1.1 补执行记录与跟投信号的分页、明确批量场景下勾选跨页保留；v1.2 补绑定传参的定向包与 TikTok 商品库口径（与主 PRD v1.9 / CR-004 同步）
## 1. 背景与范围
### 1.1 本期做什么
在既有的新剧测新链路上，本期加两件事：
| # | 改动 | 一句话 |
|---|---|---|
| 1 | 跟投信号接入 | 上游 smart_ad_put 的跟投决策信号进入本系统，用户勾选信号批量确认后绑定进 Meta / TikTok 跟投任务 |
| 2 | 绑定任务模板多选 | 「默认自动化任务」从「每个键一条配置」改为「可配多条、每条可启停」，测新与跟投两个场景一致 |
### 1.2 为什么现在做
原口径是「跟投依赖上游智能基建 smart_ad_put，本期不做两系统对接」，系统与试点范围都只覆盖新剧测新。本期决定同时推进跟投：接收端、列表、配置界面、执行记录一并建成。
另一条线来自实操。原「默认自动化任务」是「每个键一条配置，各绑一条 Meta 任务与一条 TikTok 任务」，且已覆盖的语种禁止重复新增。这条规则在真实投放里站不住：
- 同一语种 / 组合常需要同时投到多个账户包，一条配置不够
- 想临时收口某个任务，只能整条删掉，恢复时要重新配
所以把唯一性约束换成**多条 + 逐条启用状态**：约束取消，控制权交给启停。
### 1.3 跟投与测新的对比
| 维度 | 新剧测新 | 跟投 |
|---|---|---|
| 触发源 | 短剧上线 / 预上线信号（仅提醒）| smart_ad_put 决策信号 |
| 进入环节 | 信号提醒 → 新剧入测新清单 | 信号直接入「跟投信号」页 |
| 发起方式 | 用户从测新清单勾选短剧批量发起 | 用户从「跟投信号」页勾选信号批量确认 |
| 人工确认 | 有（批量级弹窗：配置列表 + 统一排期）| 有（同形态：本批信号清单 + 配置列表 + 统一排期）|
| 目标粒度 | 短剧 | 短剧 / 广告计划 / 素材 |
| 语种来源 | 信号自带 `language_code` | 信号自带 `language_code`，需经取值对照 |
| 排期 | 本批统一排期，可留空即投 | 本批统一排期，可留空即投 |
| 配置键 | 语种 | 目标维度 × 语种 |
| 配置归属 | 按当前操作人逐人一版 | 全局一版，归「系统」 |
| 操作人 | 确认人 | 确认人 |
两条路径**确认之前都不会投出去**。
## 2. 触发信号 `FOLLOW_UP`
### 2.1 字段定义（以上游实际产出为准）
上游 smart_ad_put 已按此契约产出信号并落盘，本节字段与其 `BuildSignal` 模型一致，本期不要求上游改动。
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `signal_id` | string | ✅ | 幂等键，格式 `YYYYMMDDHHMMSS_目标ID` |
| `signal_type` | enum | ✅ | 固定 `FOLLOW_UP` |
| `target_dimension` | enum | ✅ | `product` / `campaign` / `material` |
| `target_id` | string | ✅ | 目标标识（短剧 / 广告计划 / 素材）|
| `language_code` | string | ✅ | 目标语言，用于默认绑定路由。上游取值为中文名（如「韩语」「马来西亚语」），需经对照表转本系统语种 |
| `script_no` | string | 否 | 剧本编号（如 `LA011`）。用于命中本系统短剧库、补中文短剧名 |
| `shortplay_name` | string | 否 | 上游侧短剧名（英文）。本系统短剧库命中不到时用它展示 |
| `reason` | string | 否 | 决策理由（如「成长期: ROI>175.0% 且趋势上升71%」）|
| `confidence` | number | ✅ | 阶段判定置信度，0–1。数据越充分、规则越明确则越高，非盈利概率 |
| `timestamp` | datetime | ✅ | 上游信号产出时间（UTC）|
### 2.2 与上游的对接口径
本期**不要求上游改动契约**。上游已按 §2.1 产出信号并落盘（`logs/decisions/<UTC日>/decisions.jsonl`），并提供 `GET /signals` 读取当日信号。
需要双方拉齐的只有一处：**语种取值对照**。
| 上游 `language_code` | 本系统语种 | 处理 |
|---|---|---|
| 中文 / 英语 / 韩语 / 泰语 | 同名 | 直接使用 |
| 马来西亚语 | 马来语 | 对照表转换 |
| 印尼语 / 越南语 / 西班牙语 等 | — | 本系统不支持，信号确认时跳过并留痕（见 §6）|
### 2.3 原设计作废说明
本期初稿曾拟「新增 `shortplay_id`、删除 `script_no`、语种由本系统反查短剧库」三项契约变更。复核上游后发现前提不成立——上游 `BuildSignal` 已携带 `language_code`（注释写明「下游模板分流必需」）与 `script_no`，且没有 `shortplay_id`。三项**全部撤销**，契约以上游实际产出为准。
## 3. 跟投处理流程
### 3.1 主流程
```
FOLLOW_UP 信号到达 → 幂等去重（signal_id）→ 入「跟投信号」页待确认（不自动绑定）
→ 用户勾选信号批量确认 → 弹窗展示本批信号清单 + 该批涉及的「目标维度 × 语种」配置列表 + 本批统一排期
→ 确认后按各信号的「目标维度 × 语种」取该键下全部启用中的默认任务 → 绑定进这些 Meta / TikTok 跟投自动化任务 → 写执行记录
```
### 3.2 语种与展示信息
- **语种**：直接取信号的 `language_code`，经「上游语言取值 ↔ 本系统语种」对照表（§2.2）转换后用于路由；对照表未命中（本系统不支持的语种）时确认时跳过并留痕。
- **剧本编号**：取信号的 `script_no`。
- **短剧名**：按 `script_no` 命中本系统短剧库时，展示中文格式「剧本编号 + 短剧名」（与测新清单一致）；未命中时用上游的 `shortplay_name`。
三者都取自信号本体，本系统不据此判定投放资格——反查只用于展示，反查不到不影响绑定。
### 3.3 路由维度
跟投默认绑定的解析键是**目标维度 × 语种**：目标维度直接取信号的 `target_dimension`，语种由 `language_code` 经对照表转换得到。同一语种下，短剧级 / 广告计划级 / 素材级各配一组，互不通用——短剧级跟投与素材级跟投的账户包、预算、竞价本就不同，不能共用同一批任务。测新只有短剧一个维度，路由键仍是语种。
### 3.4 排期
跟投在批量确认弹窗中设**本批统一排期**（东八区），对本批所有信号生效；留空即立即执行。排期作为参数传给自动化任务，由任务到点执行。
### 3.5 绑定传参
`target_id` + 排期（`schedule_at`，东八区，可留空）+ 解析出的平台任务（每条条目各一条 Meta、一条 TikTok）+ 各平台 `audience_id`（取目标任务绑定短剧列表第一部短剧的定向包；TikTok 商品数据源开启时该平台不传此值，改由商品级定向生成）。TikTok 商品数据源开启时另传商品绑定：`account_id` + `library_id` + `product_id` + 匹配方式（自动匹配 / 同语种随机 / 全库随机）。其余执行参数（账户包 / 预算 / 竞价 / 版位 / 投放天数 / 止投）由自动化任务承载，机器投放不重复定义。
定向包与商品库的完整口径见主 PRD v1.9 §5.2 / §5.3 与 `docs/机器投放系统-需求变更-绑定定向包与TikTok商品库.md`。
## 4. 默认自动化任务（绑定任务模板）
### 4.1 配置模型
一条配置 = 键 + 绑定一条 Meta 自动化任务 + 绑定一条 TikTok 自动化任务 + 状态。
| 场景 | 键 | 配置归属 |
|---|---|---|
| 测新 | 语种 | 按当前操作人逐人一版 |
| 跟投 | 目标维度 × 语种 | 全局一版，归「系统」 |
**同一个键可配任意多条，不设上限**——不限制重复新增，新增即追加为一条新条目；每条独立带启用 / 停用状态。
解析时取该键下**全部启用中**的条目，把目标绑进它们的全部任务：
| 情形 | 结果 |
|---|---|
| 某组合配了 3 条启用条目 | 一次绑定会绑进这 3 条所涉的全部 Meta / TikTok 任务 |
| 停用的条目 | 完全不参与解析——既不绑定，也不计为异常 |
| 该键下无启用条目（未配置，或全被停用）| 跳过并提示 |
「已覆盖禁止重复新增」整条规则取消。配几条，就决定一次会投到几处。停用而非删除的用途：临时收口某个账户包 / 任务，保留配置便于随时恢复。
### 4.2 配置界面
默认自动化任务页按场景分「测新 / 跟投」两个 tab。
- 测新 tab 配置表列 = 语种 / 绑定 Meta 自动化任务 / 绑定 TikTok 自动化任务 / 状态 / 操作
- 跟投 tab 配置表多一列「目标维度」，列 = 目标维度 / 语种 / 绑定 Meta 自动化任务 / 绑定 TikTok 自动化任务 / 状态 / 操作
- 「新增配置」：选语种（跟投另选目标维度）+ 逐平台绑定任务。同一个键已存在时照常追加，不再拦截重复新增
- 每行三个操作：编辑（键固定，只调整两个平台各自绑定的任务）、启用 / 停用（逐条切换）、删除（只删这一条）
### 4.3 素材维度的任务约束
跟投在「素材」维度下，绑定任务的下拉**只列指定了素材类型的自动化任务**；短剧、广告计划维度不受限。
依据：素材级跟投的目标是具体素材，承载它的自动化任务必须声明自己处理的素材类型，否则投不到点上。
### 4.4 权限
| 角色 | 跟投配置 |
|---|---|
| 管理员 | 可增删改、可启停，可见 |
| 普通用户 | 不可见该 tab（配置是系统级一版，由管理员维护）|
测新配置的权限维持现状不变（按操作人，各见各的）。跟投的**确认动作**不设管理员限制——「跟投信号」页所有人可见、均可确认。
## 5. 运行看板与跟投信号
运行看板只剩「执行记录」一页；「跟投信号」是与之并列的独立外层页（在导航里紧挨测新清单）。两页均为纯读、无写入口：执行记录看「绑成了什么」，跟投信号看「收到了什么」。
### 5.1 执行记录
跟投复用现有执行记录页，不新增筛选项（类型筛选已含「跟投」）。
| 字段 | 跟投取值 |
|---|---|
| `signal_id` | 上游信号标识 |
| `signal_type` | 跟投 |
| `target_dimension` + `target_id` | 短剧 / 广告计划 / 素材及其标识；`script_no` 命中短剧库时目标展示为「剧本编号 + 中文短剧名」|
| 自动化任务ID | 该组合下全部启用条目所涉的 Meta / TikTok 任务，形如 `meta_a、meta_b / tt_a、tt_b`；未解析出时展示 `—` |
| 绑定参数 | 实际使用的定向包（取各任务首部短剧）与 TikTok 商品名 / 匹配方式（自动匹配 / 同语种随机 / 全库随机）|
| 操作人 | 确认人 |
| 运行 | 自动化任务运行状态（启动 / 暂停）；跳过时以文本展示原因 |
| 时间 | 信号接收与绑定时间 |
分页每页 10 / 20 / 50，查询与重置后回到第 1 页；跟投信号页与测新清单沿用同一形态。
### 5.2 「跟投信号」页
展示本系统收到的 `FOLLOW_UP` 信号本体（参照上游 smart_ad_put 的「决策日志」页），一份信号一行，不因绑定失败而不记录。执行记录看「绑成了什么」，本页看「收到了什么」——也是跟投的用户入口。
| 列 | 取值 |
|---|---|
| 勾选框 | 仅「待确认」可勾；「已绑定」的禁用。支持表头全选（自动跳过不可勾的行，且只作用于当前页）。勾选跨页保留，翻页不丢已选信号 |
| 接收时间 | 本系统接收该信号的时间 |
| 信号ID | `signal_id` |
| 维度 | 短剧 / 广告计划 / 素材（由 `target_dimension` 转写）|
| 目标ID | `target_id` |
| 短剧名 | 按 `script_no` 命中本系统短剧库时展示「剧本编号 + 中文短剧名」；未命中时用上游 `shortplay_name` |
| 语言 / 剧本 | `language_code` + `script_no`（原样展示上游取值，便于发现取值未对齐）|
| 置信度 | `confidence` 百分数展示；阶段判定可信度，非盈利概率 |
| 原因 | `reason` |
| 状态 | 待确认 / 已绑定 |
| 详情 | 弹窗展示该信号原始 JSON |
筛选：维度 / 语言 / 状态 / 目标搜索 / 接收时间范围；分页与执行记录一致（10 / 20 / 50）。
### 5.3 批量确认
列表顶部常驻批量区（已选 N 条 +「批量确认」按钮）。勾选信号后点「批量确认」进入确认弹窗，弹窗展示三件事：
1. **本批信号清单**：维度 + 短剧名（未命中短剧库时为上游剧名或目标ID）
2. **默认自动化任务配置列表**：本批涉及的「目标维度 × 语种」组合及其全部启用条目，无启用条目的组合标「未配置」；同时展示每个任务实际使用的定向包与 TikTok 商品匹配方式，仅作核对
3. **本批统一排期**：东八区，对本批所有信号生效，留空即立即执行
勾选**跨页保留**，可翻页挑选后一次批量确认。取消后勾选保留（便于重新打开继续核对）；确认后已绑定的移出勾选，被跳过的保持勾选，便于补配后直接重试。
确认结果：
- **通过并绑定**：各信号按自身「目标维度 × 语种」绑定并写入执行记录（操作人 = 确认人），随后自动跳转执行记录
- **无启用条目的信号跳过并弹提示**，且**保持待确认状态**——补配后可重新勾选确认
- **取消**：关闭弹窗，本批信号保持待确认，不写入任何记录
## 6. 异常与边界
| 场景 | 处理 |
|---|---|
| 必填字段缺失 / 维度取值非法 | 跳过·数据异常 |
| `language_code` 不在语种对照表内（本系统不支持的语种）| 跳过·无默认自动化任务 |
| 该「目标维度 × 语种」下没有启用中的默认任务（未配置，或配置全被停用）| 跳过·无默认自动化任务 |
| 任务无已绑短剧，或首部短剧无定向包 | 跳过·数据异常（正常模板不会出现）|
| 账户无可用商品库，或商品库为空 | 跳过·数据异常 |
| 同 `signal_id` 重复投递 | 幂等去重，不重复入列表 |
| 已绑定的信号再次被确认 | 不可重复确认（列表勾选框禁用）|
被跳过的信号**保持待确认状态**，不因一次确认失败而丢失——补配好该「目标维度 × 语种」的默认任务后可以重新勾选确认（与测新「跳过的短剧保持未发起」同一口径）。
`script_no` 命中不到本系统短剧库不算异常——那只是展示退回上游剧名，绑定照常进行。
不设独立告警页。异常以执行记录状态与原因文本呈现，与测新同一套机制。
## 7. 与测新的关系
跟投与测新不设互斥。同一目标可同时存在于测新任务与跟投任务中，重复消耗由自动化任务自身的预算与止投规则约束。
理由：机器投放是绑定编排层，不是生命周期裁决方。测新何时让位于跟投，属于投放策略，归自动化任务与决策端。
## 8. 开投前置
跟投在批量确认前不产生任何消耗——人工确认是投放的闸门，这与测新一致。以下三项**未闭环则不开投**：
| # | 前置 | 现状 | 归属 |
|---|---|---|---|
| 1 | 素材级决策能力 | 未闭环。上游 `StageSignalMapper` 注明 `material_*` 维度挂起，素材级无真实数据与判定能力 | 上游接入素材级数据源（打分系统素材分数 / 素材日级指标）|
| 2 | 语种取值对齐 | 未闭环。上游 `language_code` 用中文名，且含本系统不支持的语种（印尼语 / 越南语 / 西班牙语）| 双方拉齐对照表，见 §2.2 |
| 3 | 信号通道（本系统接收端）| 上游侧形态已有（落盘 `logs/decisions/<UTC日>/decisions.jsonl` + `GET /signals`）；本系统采用文件 / API / MQ 待定 | 两方共同定 |
已经闭环、不再作为前置的：
- **阶段 → 跟投映射表**：上游已定并生效（`config/signal_rules.json`：`campaign_growth` / `campaign_sustained` / `product_entry` / `product_sustained` / `product_growth`，冷却 24h）
- **信号契约字段**：上游 `BuildSignal` 已按 §2.1 产出并落盘，本期不要求其改动

## 10. 验收
- [ ] `FOLLOW_UP` 信号到达后只入「跟投信号」页待确认，不自动绑定；未确认前不产生任何消耗
- [ ] 语种取信号的 `language_code` 并经对照表转换；未收录语种确认时跳过并留痕
- [ ] `script_no` 命中短剧库时展示中文剧名，未命中退回上游 `shortplay_name`，且不影响绑定
- [ ] 按「目标维度 × 语种」解析：同一语种下短剧 / 广告计划 / 素材各配各的，互不通用
- [ ] 同一个键可配多条默认任务；解析时绑定其全部启用条目所涉的全部 Meta / TikTok 任务
- [ ] 停用的条目完全不参与解析，也不触发异常
- [ ] 新增配置不拦截「同一个键重复」——作为一条新条目追加
- [ ] 素材维度的任务候选只列「指定了素材类型」的自动化任务；短剧 / 广告计划维度不限
- [ ] 跟投配置全局一版、仅管理员可见可改；「跟投信号」页所有人可见、均可确认
- [ ] 勾选信号可批量确认；弹窗展示本批信号清单 + 本批涉及的「目标维度 × 语种」配置列表 + 本批统一排期
- [ ] 排期留空即立即执行；设了排期则作为参数传给自动化任务
- [ ] 确认后跳转执行记录，操作人 = 确认人；取消不写入任何记录
- [ ] 已绑定的信号不可重复确认（勾选框禁用）；被跳过的信号保持待确认，补配后可重新确认
- [ ] 必填缺失 / 维度非法 → 跳过·数据异常
- [ ] 该「目标维度 × 语种」下没有启用中的默认任务 → 跳过·无默认自动化任务
- [ ] 同 `signal_id` 重复投递不重复入列表
- [ ] 「跟投信号」作为与测新清单并列的页面可切换进入，列出收到的信号本体（含置信度与状态），并可弹窗看原始 JSON
- [ ] 执行记录、跟投信号、测新清单三张列表均分页（每页 10 / 20 / 50），查询与重置回到第 1 页；跟投信号与测新清单的勾选跨页保留
- [ ] 执行记录任务列列出该组合下的全部任务，可按信号类型「跟投」筛出
- [ ] 绑定时定向包取目标任务首部短剧的定向包（Meta / TikTok 分取），编排层无定向选择入口
- [ ] TikTok 商品数据源开启时按「剧本名 + 语种」自动匹配商品，失败先同语种随机、再无则全库随机；执行记录的绑定参数列展示商品与匹配方式
- [ ] 默认自动化任务页可切换测新 / 跟投；跟投配置表含目标维度列与状态列
- [ ] 跟投与测新不互斥，同一目标可同时存在于两类任务
## 11. 关键决策
| # | 决策 |
|---|---|
| 1 | 跟投由「本期不做对接」改为本期接入，系统范围与试点范围同步扩到跟投 |
| 2 | 跟投由全自动改为全量人工批量确认：信号到达只入列表待确认，勾选后批量确认才绑定；与测新形态对称，弹窗含配置列表与本批统一排期 |
| 3 | 契约以上游 `BuildSignal` 实际产出为准（`language_code` / `script_no` / `shortplay_name` / `confidence`），不要求上游改动，双方只需拉齐语种取值对照 |
| 4 | 语种直接取信号 `language_code`，经「上游语言取值 ↔ 本系统语种」对照表转换；本系统按 `script_no` 反查短剧库只为补中文短剧名，不做资格判定 |
| 5 | 短剧 / 广告计划 / 素材三粒度走同一条解析与绑定路径 |
| 6 | 跟投默认绑定的路由键 = 目标维度 × 语种；同一语种下三个维度各配一组，互不通用 |
| 7 | 跟投配置归「系统」全局一版，仅管理员可增删改；确认动作不设限，所有人可见可确认 |
| 8 | 跟投与测新不设互斥，重复消耗交由自动化任务的预算与止投规则约束 |
| 9 | 取消「已覆盖禁止重复新增」：同一个键可配任意多条默认自动化任务，不设条数上限 |
| 10 | 每条默认自动化任务带启用 / 停用状态；解析只取启用中的条目，停用既不绑定也不报异常 |
| 11 | 素材维度的任务候选只列「指定了素材类型」的自动化任务，短剧 / 广告计划维度不限 |
| 12 | 新增与测新清单并列的「跟投信号」页：展示收到的信号本体（含上游 `confidence` 与 `reason`）与状态，支持勾选批量确认，与执行记录互补 |
| 13 | 执行记录 / 跟投信号 / 测新清单三张列表分页形态统一（每页 10 / 20 / 50）；批量场景下勾选跨页保留，表头全选只作用于当前页 |
| 14 | 定向包取目标任务绑定短剧列表第一部短剧的定向包（Meta / TikTok 分取），编排层不选包、不查定向包列表 |
| 15 | TikTok 商品库本期接入：自动匹配优先，失败先同语种随机、再无则全库随机；商品库优先取任务同账户下已配的库，未配时取账户下第一个 |
