# 机器投放系统 · 需求文档：执行记录展示广告产出
> 版本 v1.0 · 2026-10-27 · 面向开发与需求评审 · 本文是本次改动的唯一需求依据；主 PRD（v1.9）与跟投 PRD（v1.2）已冻结，其中执行记录列口径与本文不一致处，以本文与线上现状为准
## 1. 背景与范围
执行记录当前只留痕「绑成了什么」——信号、目标、绑定到的自动化任务、操作人与时间，没有下游实际建出多少广告实体的结果。运营无法回答「这个信号到底建了几个广告计划、传上去几个」，只能去下游两个任务系统逐个任务翻列表。
| # | 改动 | 一句话 |
|---|---|---|
| 1 | 执行记录新增三列 | 广告计划 / 系列、广告组、广告，列内分 Meta / TikTok 两行展示数量与上传状态 |
| 2 | 产出归属 | 下游建实体时回写 `signal_id`，本系统按信号聚合 |
本次不改绑定流程、默认自动化任务、信号契约与执行记录其余列；不新增页面、不做下钻明细、不做历史回溯。
### 1.1 基线
本文以线上执行记录现有列为基线：信号ID / 类型 / 维度 / 短剧名 / 语言 / 剧本编号 / 剧本名字 / 自动化任务 / 操作人 / 时间（东八时区）。主 PRD §6.1 中的列定义为早期原型口径，与线上不一致之处不在本次改动范围。
## 2. 数据来源与归属
### 2.1 下游广告实体
下游指 Meta 自动化任务（auto_put）与 TikTok 自动化任务（auto_put_tiktok）。任务执行后逐层产出广告实体：
| 层级 | Meta 侧命名 | TikTok 侧命名 |
|---|---|---|
| Campaign | 广告计划 | 广告系列 |
| Ad Set | 广告组 | 广告组 |
| Ad | 广告 | 广告 |
每条实体带上传状态，取值与下游看板一致：待上传 / 上传成功 / 上传失败。
### 2.2 归属规则
- 下游创建广告实体时，把本系统本次编排的 `signal_id` 一并写入实体记录（两个项目均需支持）。
- 本系统按 `signal_id` 聚合：同一信号下 Meta / TikTok 两个平台、全部绑定任务、三层实体，汇总为执行记录的一行。
- 同一 `signal_id` 重复投递沿用现有幂等口径，不重复计数。
- 实体与信号不做二次推测归属；无 `signal_id` 的历史实体不参与统计。
### 2.3 数据新鲜度
- 产品要求：绑定成功后 10 分钟内，执行记录可查到该信号名下的广告实体；实体上传状态变化（含重试后由失败转成功）同样在 10 分钟内反映。
- 读取接口、同步机制与存储方式由开发期约定，不在本文锁定，满足上述时延即可。
## 3. 展示口径
### 3.1 列与位置
在执行记录「自动化任务」之后、「操作人」之前插入三列：
| 列名 | 统计层级 |
|---|---|
| 广告计划 / 系列 | Campaign（Meta 广告计划 / TikTok 广告系列）|
| 广告组 | Ad Set |
| 广告 | Ad |
其余列的位置与含义不变。
### 3.2 单元格格式
每个单元格固定两行，Meta 在上、TikTok 在下，格式为「平台 总数 (成功/失败/待上传)」，示例：
```
Meta 3 (2/1/0)
TikTok 2 (2/0/0)
```
- 括号内顺序固定为 上传成功 / 上传失败 / 待上传。
- 总数 = 三态之和。
- 某平台本次绑定跳过 / 失败，或该记录属于上线前历史信号：该行显示 `Meta —` / `TikTok —`。
- 某平台绑定成功但下游暂无实体（含排期未到）：该行显示 `Meta 0 (0/0/0)` / `TikTok 0 (0/0/0)`。
### 3.3 计数规则
- 按 `signal_id` 统计下游留存的全部实体，不论上传状态。
- 一个实体只计一次；重试不新增计数，只更新该实体状态。
- 三层独立计数：上层实体失败不影响下层已产出实体的计数。
- 以读取时下游留存的记录为准，已删除实体不计入。
- 不按创建时间窗口截断：同一信号关联的全部实体都计入。
## 4. 边界与异常
| 场景 | 展示 |
|---|---|
| 绑定成功，下游已有实体 | 正常计数 |
| 绑定成功，下游暂无实体（含排期未到）| `0 (0/0/0)` |
| 绑定跳过 / 失败 | 未绑定平台行显示 `—`；整体跳过（如无默认自动化任务）时两行均为 `—` |
| 上线前历史记录（下游无 `signal_id`）| 三列两行均为 `—` |
| 仅单平台绑定成功 | 成功平台正常计数，未绑定平台 `—` |
| 下游读取失败 / 超时 | 有上次成功值时保留上次值；无值时显示 `—`，不得以 `0` 冒充「无产出」|
| 实体全部停在待上传 | 形如 `n (0/0/n)`，正常展示 |
| 同一信号重复投递 | 幂等，不重复计数 |
## 5. 验收
- [ ] 执行记录在「自动化任务」后新增「广告计划 / 系列」「广告组」「广告」三列，其余列不变
- [ ] 单元格按 Meta / TikTok 两行展示，格式为「平台 总数 (成功/失败/待上传)」
- [ ] 下游按 `signal_id` 回写后，各信号三列数量与该信号名下实体实际条数一致
- [ ] 三层独立计数，上层失败不影响下层计数
- [ ] 绑定成功后 10 分钟内可查到产出，上传状态变化 10 分钟内更新
- [ ] 绑定跳过 / 失败与历史记录显示 `—`
- [ ] 绑定成功但下游无实体显示 `0 (0/0/0)`
- [ ] 仅单平台成功时，未绑定平台显示 `—`
- [ ] 下游读取失败且无历史值时显示 `—`，不显示 `0`
- [ ] 同一信号重复投递不重复计数
