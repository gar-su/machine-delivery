# 机器投放系统 · 需求变更单：测新清单筛选与列增强
> 变更单 CR-001 · 2026-09-16 · 目标版本 v1.4 · 影响界面：测新清单 · 对应 PRD §2.2 / §3
## 1. 背景与目标
测新清单是运营发起测新的唯一入口，展示全部短剧。上线量增长后，运营需要一次性核对一批指定短剧，也需要按上线时间判断剧的新旧。现版本清单的筛选与列不足以支撑这两件事。
| 现状 | 本次变更 |
|---|---|
| 短剧名与剧本编号共用一个搜索框，无法分别筛选 | 拆为两个独立筛选框 |
| 单个关键词一次只能筛一部 | 新增批量模式，一次筛一批 |
| 清单无上线时间，无法判断剧的新旧 | 新增上线时间列 + 上线时间范围筛选 |
| 清单无从得知某剧是否投过 | 新增初次投放时间列 |
## 2. 变更内容
### 2.1 筛选框拆分
原「短剧」单框（同时匹配剧本编号、剧本名、短剧名）拆为两个独立筛选框：短剧名、剧本编号。
- 短剧名框匹配短剧名，如输入「霸总」命中「霸总的替嫁新娘」
- 剧本编号框严格只匹配剧本编号，如输入 `LA001`
**剧本名不再可搜**：原合并框支持按剧本名检索，拆分后剧本名仍在列表中展示，但不参与筛选。
### 2.2 批量 / 单独双搜索模式
短剧名、剧本编号两个框各自带一个模式切换按钮，互相独立。
| 模式 | 输入形态 | 匹配规则 |
|---|---|---|
| 单独（默认）| 单行输入框 | 整个输入值作为一个关键词，模糊匹配（包含即命中）|
| 批量 | 多行文本框 | 按行切分，每行一个值；空行与行内首尾空白忽略 |
批量模式下同一框内多值为「或」关系——命中任一行即展示该短剧；不同筛选框之间为「且」关系。
**分隔符只认换行**：逗号、顿号等一律作为普通字符参与匹配。输入 `LA001,LA003` 会被视为一个编号，不命中任何短剧。
**切换带内容**：单独转批量时原值成为第一行，批量转单独时取第一个非空行。切换不清空已输内容，避免筛选条件被静默丢掉。
### 2.3 上线时间范围筛选
新增起止两个日期选择器，筛选上线时间落在区间内的短剧，包含首尾两天。任一端留空即该端不限。
### 2.4 列表新增两列
测新清单列表新增「上线时间」「初次投放时间」两列，位置在上线状态之前。
| 列 | 取值 | 空值展示 |
|---|---|---|
| 上线时间 | 短剧上线 / 预上线时间，含时分 | 空 |
| 初次投放时间 | 短剧初次投放时间，由上游带入 | `—` |
两个字段均由上游带入，机器投放系统不做计算与派生。初次投放时间与「本系统是否发起过测新」无关——短剧可能在本系统接入前已由其他渠道投放。
### 2.5 信号字段补充
`NEW_DRAMA_ONLINE` 信号新增 `first_delivered_at` 字段（非必填），承载短剧初次投放时间，随短剧一并进入测新清单。
## 3. 不在本次范围
- 列表按列排序 / 默认排序口径调整
- 查询后保留已勾选状态
- 剧本名参与筛选
- 后端 API 实现（本次仅后台原型与文档）
## 4. 验收
- [ ] 短剧名、剧本编号为两个独立筛选框，可分别输入
- [ ] 两个框均可切换单独 / 批量模式，按钮文案与当前模式对应，切换后已输内容带过去
- [ ] 单独模式下输入「霸总」命中「霸总的替嫁新娘」
- [ ] 批量模式下每行一个值，命中任一行即展示；空行与行内首尾空白被忽略
- [ ] 批量模式下逗号不被当作分隔符
- [ ] 剧本编号框输入剧本名（如「替嫁新娘」）不命中任何短剧
- [ ] 上线时间范围筛选包含首尾两天，任一端留空即不限
- [ ] 列表展示上线时间、初次投放时间两列，位置在上线状态之前
- [ ] 初次投放时间为空的短剧展示 `—`
- [ ] 点击查询后分页回到第 1 页
- [ ] 各筛选条件之间为「且」关系，可与语言、上线时间自由组合
