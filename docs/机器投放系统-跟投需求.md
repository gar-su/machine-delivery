# 机器投放系统 · 跟投需求（FOLLOW_UP）
> 版本 v1.0 · 2026-10-14 · 面向开发与需求评审 · 独立成文，PRD 仅在 §4 留指针
## 1. 定位与边界
### 1.1 跟投是什么
跟投是上游决策端 smart_ad_put 判定某目标（短剧 / 广告计划 / 素材）值得继续投放后，机器投放按「目标维度 × 语种」解析「系统」版跟投默认绑定，把该目标分别绑定进 Meta 与 TikTok 的跟投自动化任务。全自动，无人工确认。
与测新一致，机器投放对投放对象的唯一动作是绑定：不新建任务、不定义参数、不裁决投放生命周期。
### 1.2 与测新的差异
| 维度 | 新剧测新 | 跟投 |
|---|---|---|
| 触发源 | 短剧上线 / 预上线信号（仅提醒）| smart_ad_put 决策信号 |
| 发起方式 | 用户从测新清单勾选批量发起 | 信号到达自动发起 |
| 人工确认 | 有（批量级弹窗：配置列表 + 统一排期）| 无 |
| 目标粒度 | 短剧 | 短剧 / 广告计划 / 素材 |
| 语种来源 | 信号自带 `language_code` | 由目标所属短剧反查短剧库 |
| 排期 | 本批统一排期，可留空即投 | 无排期，立即执行 |
| 配置维度 | 语种 | 目标维度 × 语种 |
| 配置归属 | 按当前操作人逐人一版 | 全局一版，归「系统」 |
| 操作人 | 确认人 | 固定「系统」 |
## 2. 触发信号 `FOLLOW_UP`
### 2.1 字段定义
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `signal_id` | string | ✅ | 信号唯一标识，幂等键，沿用上游 `decision_id` |
| `signal_type` | enum | ✅ | 固定 `FOLLOW_UP` |
| `target_dimension` | enum | ✅ | `product` / `campaign` / `material` |
| `target_id` | string | ✅ | 对应 `shortplay_id` / `campaign_id` / `material_id` |
| `shortplay_id` | string | ✅ | 目标所属短剧 ID，用于反查语种；`product` 级与 `target_id` 同值 |
| `reason` | string | 否 | 决策理由，可读，用于执行记录展示 |
### 2.2 对上游的契约变更
| 变更 | 内容 |
|---|---|
| 新增 | `shortplay_id`（必填，目标所属短剧）|
| 删除 | 原 `script_no`。剧本编号由机器投放从短剧库反查，上游不再补 |
| 新增 | `signal_type` 取值 `FOLLOW_UP`（上游现为 `Decision.type` 动作枚举，需映射）|
| 映射 | 上游 `decision_id` → 本系统 `signal_id` |
## 3. 处理流程
### 3.1 主流程
```
FOLLOW_UP 信号到达 → 幂等去重（signal_id）→ 按 shortplay_id 反查短剧库（语种 / 剧本编号 / 短剧名）
→ 按目标维度 × 语种取该组合下全部启用中的默认任务 → 绑定进这些 Meta / TikTok 跟投自动化任务（立即执行）→ 写执行记录
```
### 3.2 语种解析
信号不携带语种，一律由 `shortplay_id` 反查短剧库取得，短剧库与测新清单为同一数据源。三种目标维度走同一条路径：短剧级用 `target_id`，广告计划 / 素材级用 `shortplay_id`，两者最终都落到一部短剧。
### 3.3 路由维度
跟投默认绑定的解析键是**目标维度 × 语种**：目标维度直接取信号的 `target_dimension`，语种由反查得到。同一语种下，短剧级 / 广告计划级 / 素材级各配一组，互不通用——短剧级跟投与素材级跟投的账户包、预算、竞价本就不同，不能共用同一批任务。测新只有短剧一个维度，路由键仍是语种。
### 3.4 一个组合可配多条，条目可启停
同一个键（测新 = 语种；跟投 = 目标维度 × 语种）下可以配**任意多条**默认自动化任务，不限制重复新增。每条各自绑定一条 Meta 任务与一条 TikTok 任务，并各自带启用 / 停用状态。
解析时取该键下**全部启用中**的条目，把目标绑进它们的全部任务：某组合配了 3 条启用条目，一次跟投就会绑进这 3 条所涉的全部 Meta / TikTok 任务。停用的条目**完全不参与解析**——既不绑定，也不算异常。
停用而非删除的用途：临时收口某个账户包 / 任务，保留配置便于随时恢复。
### 3.5 排期
跟投不传 `schedule_at`，信号到达即投。全自动路径无人工设排期的环节。
### 3.6 绑定传参
`target_id` + 解析出的平台任务（每条条目各一条 Meta、一条 TikTok）。执行参数（账户包 / 预算 / 竞价 / 版位 / 定向 / 投放天数 / 止投）由自动化任务承载，机器投放不重复定义。
## 4. 默认自动化任务（跟投配置）
### 4.1 配置界面
默认自动化任务页新增场景切换：测新 / 跟投。两个场景的键不同：
| 场景 | 键 | 归属 |
|---|---|---|
| 测新 | 语种 | 按当前操作人逐人一版 |
| 跟投 | 目标维度 × 语种 | 全局一版，归「系统」 |
跟投的目标维度取信号字段 `target_dimension`（短剧 / 广告计划 / 素材）。
一条配置 = 键 + 绑定 Meta 自动化任务 + 绑定 TikTok 自动化任务 + 状态。同一个键下可配多条，条数不限（见 §3.4）。
- 测新 tab 配置表列 = 语种 / 绑定 Meta 自动化任务 / 绑定 TikTok 自动化任务 / 状态 / 操作
- 跟投 tab 配置表多一列「目标维度」，列 = 目标维度 / 语种 / 绑定 Meta 自动化任务 / 绑定 TikTok 自动化任务 / 状态 / 操作
- 「新增配置」：选语种（跟投另选目标维度）+ 逐平台绑定任务。同一个键已存在时照常追加，**不再拦截重复新增**
- 每行三个操作：编辑（键固定，只调整两个平台各自绑定的任务）、启用 / 停用（逐条切换）、删除（只删这一条）
- **素材维度的任务候选受限**：绑定任务的下拉只列「指定了素材类型」的自动化任务；短剧 / 广告计划维度不限
### 4.2 权限
| 角色 | 跟投配置 |
|---|---|
| 管理员 | 可增删改、可启停，可见 |
| 普通用户 | 不可见该 tab（跟投无人工环节，无需查看）|
测新配置的权限维持现状不变（按操作人，各见各的）。
## 5. 异常与边界
| 场景 | 处理 |
|---|---|
| 目标短剧不在短剧库（反查失败）| 跳过·数据异常 |
| 必填字段缺失 / 维度取值非法 | 跳过·数据异常 |
| 该「目标维度 × 语种」下没有启用中的默认任务（未配置，或配置全被停用）| 跳过·无默认自动化任务 |
| 同 `signal_id` 重复投递 | 幂等去重，不重复绑定 |
不设独立告警页。异常以执行记录状态与原因文本呈现，与测新同一套机制。
## 6. 与测新的关系
跟投与测新不设互斥。同一目标可同时存在于测新任务与跟投任务中，重复消耗由自动化任务自身的预算与止投规则约束。
理由：机器投放是绑定编排层，不是生命周期裁决方。测新何时让位于跟投，属于投放策略，归自动化任务与决策端。
## 7. 执行记录
跟投复用现有执行记录页，不新增页面与筛选项（类型筛选已含「跟投」）。
| 字段 | 跟投取值 |
|---|---|
| `signal_id` | 上游信号标识 |
| `signal_type` | 跟投 |
| `target_dimension` + `target_id` | 短剧 / 广告计划 / 素材及其标识 |
| 自动化任务ID | 该组合下全部启用条目所涉的 Meta / TikTok 任务，形如 `meta_a、meta_b / tt_a、tt_b`；未解析出时展示 `—` |
| 操作人 | 固定「系统」 |
| 运行 | 自动化任务运行状态（启动 / 暂停）；跳过时以文本展示原因 |
| 时间 | 信号接收与绑定时间 |
## 8. 本期范围与开投前置
跟投由原「本期不做对接」改为**本期接入**，系统范围与试点范围同步扩到跟投。跟投是全自动路径、绑定即产生消耗，以下四项未闭环则不开投：
1. **信号通道**：文件 / API / MQ 定一种，并约定送达格式
2. **素材级决策能力**：smart_ad_put 现有素材生命周期检测基于行业经验设计、无真实素材数据，`material_*` 阶段被并入 `campaign`。需接入素材级数据源（打分系统素材分数 / 素材日级指标）并产出素材级跟投决策
3. **阶段 → 跟投映射表**：smart_ad_put 现有 lifecycle 判定（product / campaign）中，哪些阶段映射为「跟投」，需定表
4. **契约字段**：`shortplay_id` 落地、`script_no` 下线、`signal_type` 取值对齐
前 3 项为上游工作，第 4 项为两方共同工作。

## 10. 验收
- [ ] `FOLLOW_UP` 信号到达后自动解析语种并绑定 Meta / TikTok 跟投任务，全程无人工介入
- [ ] 短剧级按 `target_id`、广告计划 / 素材级按 `shortplay_id` 反查短剧库取语种
- [ ] 按「目标维度 × 语种」解析：同一语种下短剧 / 广告计划 / 素材各配各的，互不通用
- [ ] 同一个键可配多条默认任务；解析时绑定其全部启用条目所涉的全部 Meta / TikTok 任务
- [ ] 停用的条目完全不参与解析，也不触发异常
- [ ] 新增配置不拦截「同一个键重复」——作为一条新条目追加
- [ ] 素材维度的任务候选只列「指定了素材类型」的自动化任务；短剧 / 广告计划维度不限
- [ ] 排期不传，绑定即投
- [ ] 反查失败 / 必填缺失 / 维度非法 → 跳过·数据异常
- [ ] 该「目标维度 × 语种」下没有启用中的默认任务 → 跳过·无默认自动化任务
- [ ] 同 `signal_id` 重复投递不重复绑定
- [ ] 执行记录操作人为「系统」，可按信号类型「跟投」筛出；任务列列出该组合下的全部任务
- [ ] 默认自动化任务页可切换测新 / 跟投；跟投配置表含目标维度列与状态列；全局一份，仅管理员可增删改与启停
- [ ] 跟投与测新不互斥，同一目标可同时存在于两类任务
