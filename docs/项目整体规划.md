# 短剧投放全自动化链路 · 项目整体规划
> 版本：2026-08-10 · 核心目标：9 月底机器投放上线 · 排期：2026-08-17 ~ 09-30（约 7 周）
## 一、一页摘要（汇报版）
**目标**：9 月底（09-30）机器投放系统上线，打通"素材自动生产 × 智能打分 × 机器投放 × 数据回流"全自动投放链路。
**现状**：素材生产（narration_pipeline）、智能打分（LightGBM 模型）、三步流水线（auto_delivery）已具备，但均为需求侧原型（离线 demo 级脚本）；**关键缺口是机器投放系统（有设计零代码）与数据管道/账户池（完全待建设）**。
**排期**：7 周内三个里程碑——M0 立项/招聘/需求与契约冻结（08-17~08-28）→ M1 并行开发冲刺（08-31~09-18）→ M2 联调与上线（09-21~09-30）。
**编制**：产品与技术正式招聘，约 6-7 人（产品 1 + 后端 2 + 数据 1 + 前端 1 + 算法 1 + 测试 1）；**8 月底后端/数据到岗是 9 月底上线硬前提**。
**关键依赖**：数据管道接口契约 8 月底冻结、与当前系统（报表/binding/广告平台 API）正式对接、FB OAuth 权限批量修复。
**核心风险**：7 周激进排期，范围不裁剪必然顺延——**9 月底上线锁定为 MVP**（影子/小范围跟投 + 执行记录），全量替代三步流水线延至稳定后。
**下一步**：立项启动、招聘 JD 发布、与当前系统对接调研、数据契约冻结。

## 三、里程碑详案（2026-08-17 ~ 09-30）
### M0 · 立项 / 招聘 / 需求与契约冻结（第 1-2 周，08-17~08-28）
**目标**：项目立项、团队到位、需求与外部契约全部冻结，为 M1 并行开发扫清前置。
**关键交付物**：项目立项文档与规划文档定稿、PPT 归档；招聘 JD 发布并 8 月底到位（产品/后端 2/数据 1）；与当前系统对接摸底报告（报表/binding/投放任务 API、鉴权方式、数据模型）；**数据管道接口契约冻结**、账户池清单、机器投放 PRD 与数据管道需求定稿；FB OAuth 权限批量修复（业务侧）。
**验收口径**：8 月底前人员到岗、需求文档与数据契约冻结、OAuth 修复完成、对接调研报告产出。
**硬前提**：招聘 8 月底到位、数据契约 8 月底冻结、FB OAuth 修复完成——任一不满足则 M1 开工即顺延。
### M1 · 并行开发冲刺（第 3-5 周，08-31~09-18）
**目标**：三条线并行完成开发并进入集成联调。
**关键交付物**：
- 线 ① P1 集成：narration 输出 → 打分 → auto_delivery 三环节打通，人工确认收口可跑
- 线 ② 数据管道 + 账户池：素材表现数据接入（Provider 抽象）、账户状态维护流程
- 线 ③ 机器投放核心：规则引擎（composite/any + 两层冷却）→ 跟投执行（跨账户复制）→ SQLite 执行记录 → 四页面看板
- 与当前系统对接开发：鉴权刷新、限流、重试、幂等
**验收口径**：开发完成、单元测试通过、进入集成联调；P1 全流程人工确认可跑。
### M2 · 联调 + 上线（第 6-7 周，09-21~09-30）
**目标**：全链路联调、影子模式验证，09-30 机器投放上线。
**关键交付物**：全链路联调通过；影子模式（只记录不执行）验证；**09-30 机器投放上线（MVP：跟投跑通 + 影子/小范围）**；三步流水线暂并行，稳定后再退役。
**验收口径**：跟投响应 ≤30min、执行记录可查、成功率可观测、规则命中可查。

## 五、系统对接范围与复杂度
现有模块是离线 demo 脚本，落地需与当前生产系统正式对接，复杂度集中且易被低估：
| 对接面 | demo 现状 | 生产化要求 |
|---|---|---|
| 报表系统（admin.netshort.com） | auto_delivery 已对接查询 API | 鉴权刷新、限流、重试、幂等 |
| binding 系统（绑定/建任务） | 已对接，有已知绑定错位问题 | 精确 shortPlayId 匹配修复 |
| 广告平台 API（Meta/TikTok） | 部分跑通 | Provider 抽象、OAuth、封禁/限额感知 |
| 数据管道（素材表现数据） | 完全待建设 | 字段口径、SLA 30min、异常兜底 |
| 账户池 | 完全待建设 | 状态维护、标签、与现有账户体系打通 |
| FB OAuth 权限 | 91.2% 投放失败 | 业务侧批量修复授权，M0-M1 前置 |
## 六、关键路径与依赖
关键路径：**招聘到岗 → 需求/契约冻结（M0）→ 系统对接 + 数据管道 + 机器投放（M1）→ 联调上线（M2）**。
- 招聘 8 月底到岗是 9 月底上线第一前提
- 数据管道接口契约 8 月底不冻结，M1 无从开工
- 数据管道/账户池是机器投放的前置数据与执行底座
- FB OAuth 权限不修复，全链路不可验证
## 七、风险与决策点（激进排期下的硬约束）
| 风险 | 应对 |
|---|---|
| 7 周激进排期，范围不裁剪必然顺延 | 9 月底上线锁定为 MVP（影子/小范围跟投 + 执行记录），全量替代三步流水线延至稳定后；若坚持全量上线需另行追加排期 |
| 招聘 8 月底不到位 | 立项即发 JD，列为硬前提；8 月底未到岗则同步启动范围裁剪预案 |
| 数据契约 8 月底不冻结 | M1 无从开工，契约冻结列为 M0 交付门 |
| 系统对接复杂度被低估（多系统鉴权/demo→生产） | M0 出对接调研报告，M1 逐系统打通并验收 |
| FB OAuth 权限问题（91.2% 失败） | 业务侧 M1 前批量修复，否则链路不可验证 |
| 现有代码 demo 级，缺生产化健壮性 | 数据管道与机器投放按生产标准补齐（监控/重试/限流/幂等） |
| 账户池选取策略/渠道优先级未决（PPT 待对齐 5 决策） | M0 内对齐全对齐，避免开发返工 |
**待对齐决策（M0 内闭环）**：机器投放替换节奏、账户池选取策略（随机 vs 标签过滤）、渠道优先级（Meta/TikTok 并行 vs 先后）、数据管道口径、规则与阈值归属。

- **P4 智能出价**：基于竞价环境动态调整预算与出价
